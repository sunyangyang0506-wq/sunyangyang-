# 个人想法与知识沉淀

把想法的价值、推演关系、判断变化和可复用方法保存下来。保留少量必要原话作为证据，避免以逐字转录或普通摘要代替知识结构。默认中文，简洁、具体。

## 执行边界

- 仅使用本轮上下文、用户提供材料、已授权且实际可访问的连接器与项目文件。先发现相关工具并检查访问能力。
- 不声称监听全部 ChatGPT/Codex 对话，不声称安装即会后台运行。自动调用取决于宿主是否加载本技能；定时任务取决于真实调度器及数据源。
- 将“思维链路”呈现为用户公开表达的观点、依据、约束、选择及演变关系。补充的逻辑标为助手推断，不伪造用户内心过程，不要求或记录模型隐藏推理。
- 不打断正在执行的项目：先推进主任务，在有实质变化的节点追加知识记录；知识归档不等于项目完成。
- 技能规则与个人知识数据分开存储。不得把聊天原文、健康财务信息、企业资料或凭据写入技能包。知识库默认私有；目标未确定时保留待同步状态。

## 工作流程

1. **读取已有状态**：定位知识库配置、索引、相关主题及最近版本；读取实际内容，不能凭记忆覆盖。配置格式、数据模型见 `references/structure.md`。
2. **识别新增信号**：新问题/机会、新解决方案、目标变化、约束变化、观点修正、实验结果、失败原因、可复用方法。寒暄、重复表达和无新增信息的状态询问不新增卡片。
3. **提炼价值**：写清解决谁的什么问题、为何值得做、核心机制、成立条件、验证方法。缺少证据时明确“待验证”，不编造市场价值或成果。
4. **建立关系**：按稳定 ID 关联同主题的想法、问题、假设、决策、行动、结果、方法。区分深化、分支、反证、替代、合并、复用；跨主题关联必须说明共同机制及适用差异。
5. **追加演变**：记录旧观点→新观点、触发证据、取舍和影响。保留被否定路径，不覆盖历史。用户纠正优先于助手推断；保留纠正记录。
6. **关联项目**：给出项目 ID、当前真实阶段、下一步、验收标准、阻塞。用工具结果证明实际执行；建议、已计划、已执行、已验证分别记录。
7. **生成视图**：使用 `assets/idea-card.md` 生成可读卡片，同时保存结构化 JSON 和演变事件。关系存在分支或反馈时生成紧凑 Mermaid 图；简单线性关系用表格。图中节点引用真实 ID，虚线表示推断，图旁注明依据。
8. **核验与保存**：查重、核对来源、检查 ID/引用与时间，原子写入；按 `references/sync-and-review.md` 做安全 Git 同步及停更回顾。失败保留本地变更并记录原因，不宣称已同步。
9. **简短回执**：只汇报新增/修订了什么、关键判断变化、来源覆盖及保存状态。提供知识文件或仓库的真实链接；没有可验证地址就不编造。

## 从想法到知识库的自动构建

在每次有实质新增的沉淀、48 小时停更回顾和用户要求重整知识库时，执行 `references/knowledge-construction.md`。默认完成可逆的分类、关联、索引与视图更新，不要求用户逐条指示归档。先读取已有知识库，再提炼知识、比较全局结构、实施必要的增量重构。

将“捕捉想法”和“构建知识库”视为两个交付层次：前者保存观点与变化，后者形成概念、问题、方法、证据和适用边界之间的可检索体系。不得仅追加卡片就声称完成知识库构建。自动化规则已保存、一次构建已执行、后台调度已运行分别报告。

## 质量底线

- 每条事实、用户判断、助手推断均标类型和证据；仅有会话摘要时标“摘要来源”，不得加引号冒充原话。
- 记录来源实际发生时间与采集时间；缺失时间留空，不把采集时间冒充对话时间。
- 可检索、可追溯、可比较版本；重复输入不重复生成同一事件。
- 用户价值不限于商业价值，也包括理解问题、改善生活、降低不确定性、形成方法。
- 不为了凑字段扩写。没有新证据时允许“无实质变化”。

## 自检样例

- 用户先要自动记原话，后强调想法价值与层层展开：保留一个主题，追加目标深化事件，不生成两个无关主题。
- 用户要求全部自动监听，但只有当前会话：记录诉求与能力缺口，不宣称全量监测已启用。
- 已有想法后来试验失败：追加反证与适用边界，不删除原始假设，不把未验证归因为事实。
- 同一资料重复导入：更新采集记录或跳过，不复制卡片。
