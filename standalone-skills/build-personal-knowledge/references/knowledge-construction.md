# 知识提炼与结构重建

## 构建流程

1. 读取配置、全局索引、主题定义和关联对象；按实际可访问范围建立覆盖清单。不能读全库时只重构已覆盖部分并标注范围，不宣称全量重建。
2. 从想法、决策和执行反馈提炼概念、问题、原则、方法、案例与未解问题。每个知识对象记录结论、成立条件、反例、证据、适用与不适用范围、来源想法 ID、关联项目、版本及可信状态。
3. 区分个人主张、待验证假设、单案例经验、已支持结论。一个成功案例不能自动升级为普遍规律。记录失败案例和矛盾证据；用户观点变化不自动推翻客观事实。
4. 与现有知识对象比较：复用相同概念的稳定 ID；通过 aliases 统一同义词；给重复对象建立 canonical_id，不删除原始记录。相近但条件不同的知识保留差异。无法确定同义时保存候选关联。
5. 按领域、问题、方法、项目建立多维索引，避免强行放入唯一文件夹。知识对象采用稳定路径，分类在索引中表达。主题划分应由已有材料支撑，不预先制造空目录或过度细分。
6. 新内容使原分类混杂时拆分主题；多个主题共享同一机制时增建方法节点；概念重名时区分定义；证据冲突时建立争议节点。仅关键词相似不足以合并。
7. 创建结构变更记录：触发来源、旧结构、新结构、ID 映射、受影响对象、变更理由、迁移版本和回退方式。保留源记录、旧索引与演变历史；分类变化不改变内容身份。无需逐项确认即可执行可逆重构；不得自动删除源证据或改变共享权限。
8. 从规范对象生成全局导航、主题页、问题索引、方法索引、项目关联视图和知识关系图。每个视图包含来源覆盖、生成版本和待验证项；主题页说明已有认识、分歧和下一项验证。只有真实分支或反馈关系才绘图。
9. 在暂存版本检查 ID 唯一、引用有效、来源覆盖、冲突未被隐藏、旧 ID 可追溯，成功后切换当前索引；失败保留原版本。重复输入且结构无变化时不新增内容版本，不反复改分类。
10. 按既有同步规则保存；回执明确新增知识、结构变化、待验证问题及真实同步状态。

## 最小数据扩展

保持现有 ideas、evolution、sources 格式；为旧配置添加以下结构时保留旧字段及旧版本，记录 schema 迁移：

- `knowledge/<id>.json`：id、type（concept/problem/principle/method/case/open_question）、title、statement、conditions、counterexamples、evidence_ids、idea_ids、project_ids、relations、epistemic_status、aliases、canonical_id、revision。
- `taxonomy.json`：主题稳定 ID、定义、父主题 ID、成员 ID；允许多主题归属，禁止循环父子关系。
- `indexes/`：按主题、问题、方法、项目生成的索引。
- `views/`：可重建的导航页、主题页、关系图；不得作为唯一事实来源。
- `restructures/<version>.json`：原因、前后版本、ID 映射、影响范围、检查结果与回退指针。

可视化引用真实知识 ID；助手推断的关系标注为推断。无可访问的知识库数据时只报告规则更新或构建草案，不声称已重建真实知识库。

## 自动执行边界

沿用停更 48 小时规则：依据实际来源最后活动时间与内容指纹确定是否需要回顾。调度器、数据读取权限、私有归档目标缺一时记录缺口。Skill 被加载并获得可访问材料后可自动执行上述流程，但不能自行监听未开放的聊天历史。

## 验收场景

- 新想法与已有主题同义：复用对象并追加演变，重新生成关联视图，无重复知识。
- 同一方法出现在两个项目：建立跨项目方法节点，同时保留各自适用条件与证据，不能直接认定通用有效。
- 新证据否定旧结论：保留旧版本，更新可信状态与争议关系，关联受影响项目。
- 全库分类失效：生成可回退的结构迁移，旧链接依然可定位；原始来源数量不减少。
- 重复执行同一输入：规范对象、结构版本和事件数不变。
