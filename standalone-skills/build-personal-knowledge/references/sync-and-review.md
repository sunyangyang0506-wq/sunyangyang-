# Git 归档与停更回顾

## Git 保存

1. 发现可用 Git/API 能力，核验目标、所有者、可见性、分支与现有内容。用户已授权的常规私有归档无需反复确认；公开发布私人或企业资料需要具体授权，默认不公开。
2. 若目标未确定，先查现有专用知识库，仍无结果则保存待同步内容并只询问必要的目标选择。不能因为连接 GitHub 成功就宣称知识库已建立。
3. 区分技能的安装保存与知识数据的 GitHub 归档。前者成功不能替代后者。
4. 拉取最新基线，只提交本次知识相关路径；检查 diff，排除凭据、临时文件、无关修改及未获授权的敏感原文。
5. 优先原子提交结构化对象、可读卡片、演变与索引。并发更新使用预期 SHA 或普通非强制推送；冲突时重读并合并事件，最多重试三次，绝不强推覆盖历史。
6. 回读远程路径/提交 SHA 核验成功后才标 synced。失败注明本地保存与远程失败各自状态。不要递归创建“同步状态更新”提交。

## 48 小时停更回顾

- 默认时区 Asia/Shanghai，阈值 48 小时，可配置。
- 获取实际可访问范围内的对话更新时间；时间未知时标“无法判断停更”，不得把工具查询时间当成最后对话时间。
- 对满足 `now - last_message_at >= 48h` 的主题读取完整可访问会话及关联项目证据，记录实际覆盖范围和缺口。不可访问的会话只记为未覆盖。
- 比较上次回顾的来源指纹；无变化跳过。恢复对话后开启新修订周期；跨过阈值再次回顾。
- 回顾产出：原始问题、展开/分支关系、关键转折与证据、已采取行动与结果、当前结论、未决问题、可复用方法、下一步验证。
- 停更不等于完成，也不等于失败。不得用缺少更新推断用户态度。

## 自动运行配置

用户要求自动运行时，发现 Automations 等真实调度能力，检查重复任务、可用历史数据源和执行权限。仅当定时环境能读取源数据并写入目标时才称“自动归档已启用”。可以先创建检查任务，但必须称为“检查/提醒”，不能称为具备全量读取能力的归档任务。

可用任务指令：每天按配置检查已授权来源；只回顾停更至少 48 小时且自上次回顾有变化的主题；使用 build-personal-knowledge 提炼并安全保存；报告来源覆盖和失败，遇无新增时不重复输出。

Skill 本身不提供后台进程、全局监听或 ChatGPT 历史导出接口。若未接通数据源，保留配置与规则，明确报告尚未启用，当前对话仍可主动沉淀。
