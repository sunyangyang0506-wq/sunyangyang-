# 小红书笔记全流程发布

按用户目的选择终点：准备素材、平台草稿、指定时间发布或立即发布。已有稿件从对应环节继续。商品 SKU、库存和店铺交易需要不同的商家流程。

## 首次使用与后续运行

先确定本次终点。第一次配置按 references/first-run.md 在同一轮集中收集意图并实际连接所需通道。复用用户已经提供的选题、账号、发布范围和频率。再次运行先读取对应用户、账号和栏目的私人配置，核验仍有效的授权与连接，仅处理缺失或变化的项目。准备稿件、临时发布和持续自动发布各自按用户选定范围执行。

每次进入发布流程，先按目标账号和稿件标识查询已有回执和近期作品；已经预约、审核中或已公开，立即返回对应记录。没有回执才开始制作或恢复，提交按钮前再完成原子占用并写入“提交中”。

## 从方向到成稿

只有栏目方向时，从授权资料提取候选问题，按与读者的相关性、证据是否充分、时效和与近期作品的重复程度选出本期主问题。指定选题或已有正文时直接沿用。在授权的自动栏目内自行选题。把读者、主问题、可验证材料和读完后能采取的行动写成简短提纲，然后写稿；来源不足则换有证据的切入点。留存每期选题与关键出处，便于查重和更正。

1. 整理简报。记录目标读者、要回答的一个问题、素材来源、账号、笔记类型、时区、指定终点。提炼一个有材料支撑的选题；涉及新闻、热词或数字时核对时间和出处。把未证实的意见写成意见。缺少私人经历时用观察或演示场景。
2. 写稿。图文按 references/xiaohongshu-alive-writer.md；口播按 references/alive-oral-scriptwriter.md。使用作者授权的样文作为语气参考。输出标题、正文或逐字稿、摘要和相关标签。热点标签需有当期证据。
3. 制作素材。按 references/personal-visual-storyteller.md 编排封面及配图，或完成口播音视频与字幕。读取并检查实际文件。从首图到末图逐一预览，记录文件名、顺序、来源、授权和版本；视频核对画音同步、时长与字幕。缺少生成能力时交付分镜及已有素材，标明缺项。恢复历史发布包时只按指定日期和来源读取。
4. 固化发布包。保存最终正文、媒体清单、版本、账号和稿件唯一标识；正文或图片变化时递增版本。按 references/xiaohongshu-publish-orchestrator.md 检查事实、隐私与平台当前表单要求。准备模式至此交付；尚缺图片时标明“素材待补”。
5. 执行。优先使用已获授权的小红书发布工具，否则使用实际可操作的创作后台。打开发布页，核对账号，按序上传可读文件；填入标题、正文、标签，回读后台内容和预览。草稿模式保存并回读草稿；定时模式核对日期、时区并留存预约记录。正式提交须有覆盖本账号及内容的发布授权。无法登录或遇到二次验证时保留进度。
6. 防重复。按平台、账号、稿件标识查询持久记录和后台近期作品，复用已有草稿。对同一稿件串行处理；多任务场景使用共享存储唯一记录或原子占用。不能可靠互斥时避免并发提交。点击前写入“提交中”；超时或中断先查后台，不重复点击。确认未提交才能重试。
7. 核验。区分已保存草稿、已预约、审核中、已公开、明确失败、结果待核验。记录后台证据、作品 ID 或链接、时间及版本。定时任务只有实际上线后才记录已公开；已有预约与回执的重复运行返回原记录。仅按可访问的真实指标复盘，记录采样时间。

## 同一份简报跨会话发布

从产生简报的任务读取本次北京时间日期、原稿和原始媒体。制作完成时把发布包保存到之后的任务也能读取的私人文件位置；记录可取回文件的持久标识、日期、顺序和校验值，再将其交给发布步骤。引用另一会话的临时路径时，先在原会话取回，或用实际可读取的持久副本。只有文件名、文字摘要或旧日期的同名图片时标记“待取原件”。在原件仍可读取的制作任务内优先直接发布。

优先复用已登录的创作后台，从页头核对账号。在目标稿件已有明确发布授权时自动完成上传、预览、提交和回执核验，避免再次索取同一授权。每日任务使用平台、账号、北京时间日期与栏目组成稳定稿件标识，跨会话沿用同一记录。

### 无人值守的附件交接与恢复

生成端在结束本次运行前，将原始图片、实际发布正文和按序列出每个文件 SHA-256 的清单打入同一 ZIP。使用已授权的私人文件存储实际上传，取得文件 ID；在独立临时目录按该 ID 下载并校验包与清单，确认日期、数量及全部图片可解码。将文件 ID、版本和 ZIP 校验值写入发布端可读取的私人任务记录。只给出临时路径或文件名不算完成交接。

同日重跑先检查此前发布回执，再从相同日期的持久标识或生成端仍能读取的原始 ZIP 恢复。发布端自动下载并验证后续接执行步骤。原件不可读时保留“待恢复原件”状态并记录具体失败步骤，在下一次有可用来源时接续；按首次配置的配图策略处理：要求原件时停在待恢复；已明确允许重制时用核实过的同版正文出新版、标记来源和新版本并重新验图，沿用原稿件标识。不得以其他日期图片替用或要求用户搬运文件。若上一次可能已提交，先在后台核验再重试。


## 自主登录与实际发布（v1.2.0）

用户已明确授权发布时，不要反复要求用户提供同一授权、转存附件、复制文案或自行点击发布。优先在**具备浏览器操作或平台官方发布接口的执行环境**直接执行以下步骤，直到得到后台回执；但 Skill 本身只是工作流程，不会凭安装而获得浏览器控制、账号会话或发帖权限。

1. **发现真实通道。** 检查本次执行身份可用的官方发布工具、浏览器控制能力及可访问的创作后台。只读浏览器标签、普通网页检索、历史对话中“已登录”的说法，不代表可以操作当前登录会话。不得把没有执行能力的工具说成已连接。
2. **自主复用会话。** 在可操作浏览器中打开平台创作后台，读取页头当前账号与会话状态；目标账号一致且有效则直接继续，避免重复登录。未登录时，主动打开平台提供的合法登录入口，使用已授权的账号登录方式完成可自动完成的步骤。绝不索取、存储或绕过密码、短信验证码、扫码、滑块、设备信任或其他二次验证；平台要求本人操作时仅请求该项最小必要交互，完成后自动续跑。不得通过盗用 Cookie、浏览器配置或规避反机器人措施来模拟登录。
3. **素材原样恢复。** 对同日稿件先按稳定稿件 ID 检查持久回执与后台笔记管理。若尚未发布，从用户授权的私人存储按真实文件 ID 取回当日 ZIP，或从原任务仍可访问的文件读取；解压并核对 SHA-256、7张PNG、顺序、日期、文字和可解码性。缺图时优先检查同日 ZIP；不得用其他日期图片替换或默默重新生成。没有实际读取权限时保留精确阻塞状态。
4. **后台查重与上传。** 在目标账号笔记管理按日期、标题和内容指纹查找已公开、审核中、草稿及预约记录。已存在时停止重复提交并返回原记录。否则创建/复用草稿，按原顺序上传媒体，填写标题、正文、标签；从后台逐一回读图片数量、首图、文本、日期和可见范围。不得仅凭本地素材检查推断后台上传成功。
5. **提交与回执。** 发布授权覆盖本账号和本篇内容、平台校验通过、无重复且有真实可点击发布通道时才提交一次。提交前持久写入 `SUBMITTING` 并执行互斥锁；点击后查询笔记管理确认 `UNDER_REVIEW`、`PUBLISHED`、`FAILED` 或 `UNKNOWN`。记录账号、北京时间、稿件 ID、媒体 SHA-256、后台作品 ID/链接（如有）及原始回执。超时或未知状态先查后台，禁止盲目重试。
6. **真实阻塞才通知。** 没有可操作浏览器、账号会话不可用、需要本人验证码、平台拒绝上传或无发布接口时，停止在对应节点；记录 `BLOCKED_NO_BROWSER_CONTROL`、`PENDING_LOGIN_VERIFICATION`、`PENDING_MEDIA_ACCESS` 等准确状态。不得声称“已登录”“已发布”“自动续传已启动”，也不得声称可在当前聊天中自行切换至另一个执行模式。仅当实际环境提供该能力时，才从可操作环境续跑；向用户报告唯一必要的下一步。

### 交付验收
- **登录成功**：能从当前可操作后台读取目标账号身份和登录状态。
- **上传成功**：后台预览实测媒体数量、顺序及正文一致。
- **提交成功**：后台有明确提交/审核回执，不能用点击动作代替回执。
- **公开成功**：笔记管理显示公开，尽可能附笔记 ID、链接和时间。
- **Skill 更新成功**：仓库提交和文件版本可以读回；不代表平台发布能力已部署或验证。


## 权限确认与最小授权（v1.3.0）

**目的：让 Skill 主动检查、确认和请求实际所需权限，而不是反复询问用户是否同意，也不是把用户口头同意当成平台已经授权。** 每次发布前运行 `permission_preflight`；仅可基于实际工具返回、后台可读证据或本次明确用户授权给出“已确认”。不通过时精准定位缺项并触发相应原生授权流程。Skill 无权自行授予浏览器、平台或文件权限。

### 权限检查矩阵

| 权限域 | 需要的实际证据 | 不满足时 |
| --- | --- | --- |
| 用户意图授权 | 明确指定目标账号、单篇/持续发布、公开/草稿、允许自动提交的范围；复用仍有效的历史明确授权 | `PENDING_USER_AUTH`，只询问未明确的范围 |
| 执行工具权限 | 本次执行环境实际列出可调用的网页操作或平台发帖工具，且允许执行写操作 | `BLOCKED_NO_BROWSER_CONTROL` / `BLOCKED_NO_PUBLISH_TOOL`，不要将只读浏览器当作可操作 |
| 平台身份权限 | 可操作的创作后台当前会话有效，实际读取账号昵称/标识并与目标账号一致 | `PENDING_LOGIN` / `ACCOUNT_MISMATCH`，启动平台原生登录或切换流程 |
| 平台发帖权限 | 实际可访问图文发布入口、上传控件及提交权限；无账号限制、封禁或未满足的创作者资质提示 | `PENDING_PLATFORM_PERMISSION`，使用官方申请/开通入口；不声称权限已获得 |
| 媒体读取权限 | 对当日ZIP及全部媒体逐一实际读取、校验，跨会话存储文件ID可取回 | `PENDING_MEDIA_ACCESS`，尝试同日ZIP与已授权持久副本 |
| 平台上传权限 | 原生上传控件可用且媒体上传完成、后台预览顺序/数量回读一致 | `PENDING_UPLOAD_PERMISSION`，在原生界面完成授权，失败不跳过 |
| 提交与可见性权限 | 目标账号、可见范围、内容版本、授权范围一致，后台允许提交 | `PENDING_PUBLISH_PERMISSION`，仅在用户授权缺失时再请求确认 |
| 安全验证 | 平台要求短信、扫码、验证码、滑块、设备确认时，由本人在官方界面完成 | `PENDING_LOGIN_VERIFICATION`，不绕过验证、不读取或保存凭据 |

### 实际执行规则

1. **发现与确认。** 检查实际工具、连接状态、读写权限、登录会话、账号、内容范围、上传及提交入口。优先用只读查询确认权限，避免发布测试笔记或执行不可逆操作作为权限探针。对于不能无副作用确认的提交权限，标为 `UNVERIFIED_UNTIL_SUBMIT`，而非声称 `GRANTED`。
2. **权限状态区分。** 每项输出 `GRANTED`、`DENIED`、`EXPIRED`、`UNKNOWN` 或 `USER_ACTION_REQUIRED`；同时保存证据类型、校验时间、执行环境、账号、授权范围与失效条件。历史“登录完成”仅代表当时状态，不自动继承为本次 `GRANTED`。
3. **最小授权申请。** 仅在确实缺失时调用平台或连接器提供的原生连接/授权流程。权限扩大、账号切换、从草稿改为公开或从单次改为持续发布，需要相应范围的明确授权。若平台要求本人扫码/验证码，仅提示这一项；验证完成后自动重跑检查。不得代用户批准权限、篡改权限设置或伪造授权回执。
4. **发布门禁。** 必须满足用户授权、执行工具可写、账号一致、平台发布入口可用、素材校验、后台查重、预览一致，才允许提交。任何 `DENIED`、`EXPIRED`、`UNKNOWN` 或 `USER_ACTION_REQUIRED` 的**必要**权限都应阻断依赖该权限的操作；不影响独立的制稿、校验或存档步骤。
5. **持久记录。** 私人任务记录保存 `permission_check_at`、`execution_environment`、`target_account`、`authorized_scope`、`permissions[]`（`name/status/evidence_checked_at/evidence_type/blocker`）、`next_required_action`、`publish_state`；不保存密码、Cookie、访问令牌、验证码或完整会话数据。证据仅保存不敏感摘要与可取回引用。
6. **复核与撤权。** 每次任务运行重新核验会话与关键权限；发现用户撤回授权、账号不一致或平台权限失效，立即停止上传/提交。对已提交但回执未知的笔记先查后台，不因权限恢复自动重发。

### 权限确认报告（仅在阻塞或用户要求时展示）

```text
目标账号：<后台实际确认的账号或未确认>
用户发布授权：GRANTED / PENDING_USER_AUTH
浏览器/发帖工具写权限：GRANTED / BLOCKED / UNKNOWN
登录会话：GRANTED / EXPIRED / UNKNOWN
平台图文上传/发布权限：GRANTED / UNKNOWN / DENIED
当日素材读取：GRANTED / PENDING_MEDIA_ACCESS
重复发布检查：PASS / BLOCKED / UNKNOWN
当前节点：<真实执行节点>
下一项必要操作：<仅列真正缺失的一项>
最终状态：PUBLISHED / UNDER_REVIEW / PENDING_* / BLOCKED_*
```

**验收标准：** 能明确区分“用户同意发布”“工具具备操作权限”“账号已登录”“平台允许上传”“平台允许提交”五类不同授权；每项有真实证据或明确标为未知。不能因为新增了本节就声称已获得权限或完成发布。
