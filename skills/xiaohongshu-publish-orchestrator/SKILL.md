# 小红书笔记全流程发布

按用户指定终点执行：素材、平台草稿、预约或公开发布。已有正文从恢复与校验开始；要求原样同步时保留全部内容、顺序、标题层级、数据、表格、图注及来源，不改写为短版。用户已明确授权的账号、内容范围和公开方式沿用，无需重复确认；Skill 更新和定时配置成功不等于笔记已发布。

## 已选择 Mac 执行时
依照 [Mac 日常执行与验收](references/mac-runtime.md) 运行。云端只制稿和交接，Mac 是小红书唯一发布端；不得因缺云浏览器或云会话而重启迁移或创建第二个提交者。用户明确选择的运行方式保存在私人部署配置中，通用仓库不保存个人配置。安装更新、定时配置、实际运行及后台公开回执分别验收。

## 按需读取

- 首次配置或账号、范围变化：[首次配置](references/first-run.md)。复用已有配置，只补真正缺项。
- 需要新写稿或优化文稿包装：图文读[写作参考](references/xiaohongshu-alive-writer.md)，口播读[口播参考](references/alive-oral-scriptwriter.md)。新制或优化封面读[人物与现场封面](references/personal-visual-storyteller.md)，可选“人物场景＋醒目大字”或“真实现场＋简洁主题”，按题材与可用素材选择。原稿同步不默认调用重写或重制流程。
- 执行任意发布：[发布检查与结果](references/xiaohongshu-publish-orchestrator.md)。
- ChatGPT 附件、长文插图、浏览器断连或每日补查：[恢复与长文发布](references/recovery-and-longform.md)。
- 用户已选择 Git 私有归档：[私人内容仓库](references/private-archive.md)。归档是独立步骤，默认不阻断已有完整原件的发布。
- 每日跨会话生成与自动发布：[每日执行契约](references/daily-pipeline.md)，使用随附脚本校验原包、转换上传副本并原子占用提交；它不替代实际浏览器和后台证据。

## 每次执行

新制作的文稿与封面先明确读者在意的主问题，标题具体、开头及时兑现承诺、封面有视觉主体。避免只用日期、长摘要和默认纯文字模板作为封面。两种风格都是创作选项，不要求本人出镜，不照搬参考人物或品牌；事实、来源、隐私和原样同步要求优先。风格更新适用于后续制作，不自动改动或重发已提交笔记。

1. **先记进度并查重。** 用平台、目标账号、栏目和用户指定时区的稿件日期构成稳定标识。收到触发立即写入私人记录，再检查笔记管理、回执及草稿。同日同栏目已经预约、审核中或公开则只同步状态；未通过则保存平台原因并报告，不自动重发。上次准备提交、提交中或结果不明时，以后台为准；无法排除已提交就不再次点击。
2. **核实来源和当前通道。** 读取指定日期完整原稿及实际媒体，核对源聊天或 Page 的日期和内容。旧聊天无更新时查同名聊天和其引用 Page，不能只看摘要断言缺稿。发布端实际检查浏览器、账号及入口，不沿用生成端“浏览器不可用”的环境结论。来源、账号和目录等用户配置保存在私人记录，不写进公开 Skill。
3. **准备完整发布包。** 有新选题需求才检索、写稿及制图；同步现成稿件则恢复原文原图。区分事件日期、报道日期和历史资料。脱敏用户姓名、联系方式、账号、可识别经历及内部项目；保留新闻人物姓名。检查图片中的文字、账户栏和背景。将专有引用换为可读的原始链接，不静默丢弃来源。图片预期数量来自当期清单，不把某期的七张当作所有稿件固定要求。
4. **恢复媒体并验图。** 真正读取文件字节，核对日期、清单、哈希、可解码性、顺序和图注，逐张查看。跨会话临时路径只是线索；在原会话、同日 ZIP 或已授权私人副本中取回原件。缺图时保留原位置及缺项，不标完成；禁止用往期图片替换或默默重制。
5. **创建或恢复唯一草稿。** 核对后台已有正文和图片，从中断处继续。图文顺序上传；写长文则按段落对应位置插入。上传后回读数量、顺序、相邻图注、正文完整性、来源及隐私。表格不兼容时按原行转成带列名段落，保留全部单元格。去除临时定位标记，生成并检查预览、标题、页数和可见范围。
6. **单次提交并核实。** 只有授权覆盖、账号正确、必需检查通过、无重复、预览完成才提交。先在共享私人记录中占用该稿件并写入 `SUBMITTING`；同一标识串行操作。点击后查笔记管理，区分 `UNDER_REVIEW` 与 `PUBLISHED`。点击、页面跳转、工具返回或 Git 提交均不能替代后台回执。只有明确未提交才可重试。
7. **交付与续传。** 保存素材、最终正文、图片清单、版本、尝试时间、草稿阶段、后台证据和阻塞。成功报告一次，后续只同步变化。登录、设备锁定或隐私问题需要本人操作时说明唯一必要动作；恢复后先查重、核对当前草稿再继续。缺稿、缺图或可恢复失败按既有补查窗口续跑，最后窗口报告具体进度。不得在后台未知时声称成功。

## 必要权限与证据

每次检查用户授权范围、当前执行工具可写能力、实际目标账号会话、原件读取、上传完成和提交入口。记录各项 `GRANTED / DENIED / EXPIRED / UNKNOWN / USER_ACTION_REQUIRED`、证据时间及阻塞；无法无副作用验证的提交能力记为待实际提交验证，不能用测试笔记探测。必要权限未满足则停止依赖步骤，继续可独立完成的取稿、校验或归档。

平台登录或设备验证由合法原生流程完成；需要本人操作时保留草稿并交接。遵守当前工具关于验证码、权限变更和安全提示的要求，不提取 Cookie 或规避验证。用户同意发布、工具可操作、平台已登录、上传成功和公开成功是不同事实，分别举证。

## 状态契约

主链：`STARTED → SOURCE_READY → MEDIA_VERIFIED → DRAFT → PREVIEW_VERIFIED → SUBMITTING → UNDER_REVIEW / PUBLISHED`。

异常：`BLOCKED`（写明节点）、`UNKNOWN`（可能已提交）、`REJECTED`（平台未通过）。归档单独记录 `NOT_CONFIGURED / PENDING / VERIFIED / BLOCKED`，不要把归档成功当作发布成功，也不要把可选归档失败当作发布失败。

私人记录至少包含：稿件标识、日期/时区、来源标识及版本、原文和媒体路径、按序图注及哈希、目标账号、授权范围、权限检查、尝试时间、草稿阶段、已插入与已加载图数、预览检查、提交意图、结果及审核状态、证据引用、当天已通知问题。先原子写入提交意图；若无可靠共享锁，就避免同一稿件并发提交。不保存密码、验证码、令牌或完整会话数据。
