# 私人发布包与 Git 归档

只在用户选择跨会话持久存储或 Git 归档时使用。公开 Skill 仓库保存通用工作流；日报、原图、账号标识、源聊天 ID、本机私人路径和发布回执留在私人配置及私人内容存储。不得因为目标私人仓库不存在而改写到公开仓库。

## 来源与可选归档分开

在私人配置记录内容仓库、分支、栏目、时区、源聊天/Page、目录和授权范围，不在通用 Skill 硬编码具体用户仓库或日期。先核验仓库元数据确实为 private，读写能力与本次操作相符；名称不是权限证明。缺少创建仓库接口时记录 `PENDING_PRIVATE_REPOSITORY_CREATION`，不伪造建仓成功。

当来源 ZIP 或本地原件已完整可读且用户授权直接发布时，远程归档失败不阻断本地平台发布。将 `archive_state` 与 `publish_state` 分开保存；平台发布后可再补齐已授权备份。只有用户明确要求“必须先归档”时才把归档作为门禁。

## 发布包契约

推荐同一日期目录保存 `brief.md`、`xhs-package.zip`、`manifest.json` 和 `publish-status.json`。其中：

- 正文保存完整版、原始来源链接、事件/报道日期、事实与分析边界、图注及行动；历史材料标明历史，未重验的历史档案标为未重验。
- ZIP 包含当期标题、正文、摘要、标签、实际媒体及清单。manifest 保存稳定稿件标识、时区日期、版本、来源引用、预期数量、图片顺序/图注/哈希；ZIP 自身哈希保存在包外的交接记录。预期图片数按当期稿件确定。
- 状态记录尝试时间、权限证据、草稿阶段、提交意图和真实后台回执；没有作品 ID/URL 就留空，不编造。Git 成功不能使笔记自动变成已发布。
- 跨会话交接须从独立目录真实取回字节并校验。只有文件名、临时路径或“上传成功”的文字不算交接完成。

## 提交与远端读回

先检查目标日期是否已有相同内容或人工修改，避免覆盖。校验原包、媒体顺序、可解码性和哈希后，使用已授权的 Git 或连接器提交。工具不支持大文件时保留原件并报告，不提交空壳链接。凭据由安全运行环境提供，不进入日志或仓库。

提交后按返回提交号重新读取远端正文和清单；包与媒体需要实际字节读回校验。全部一致才标 `VERIFIED` 或 `GIT_ARCHIVED`。仅有本地 commit、推送返回或清单文件不能证明所有二进制已归档。远端不可读取时保持待核验，不覆盖发布状态。

若用户的专用内容项目确实提供 `scripts/daily_pipeline.py`，先检查脚本及参数再使用其 `archive`、`push`、`fetch`、`verify-remote` 等命令；本 Skill 不承诺该脚本已安装或已部署。GitHub Actions 归档校验不等于生成日报，也不等于能够操作用户本机浏览器发布。

发布端优先读取用户配置的可用持久来源；取件后仍须完成平台账号核对、后台去重、预览、单次提交及回执。源端“浏览器不可操作”只说明源端环境状态，不能代替本地实际连接检查。
