# Mac 日常执行与验收

用户选择 Mac 后，保持一个已启用的发布工作流。云端生成器只生成和交接；没有新的迁移指令，不建立云端发布任务。不把当前远程执行环境当成 Mac，不把改提示词、推 Git 或装 Skill 当成本机部署成功。

## 私人部署配置

在 Mac 可持久保存的用户私有工作目录维护部署配置：execution_host=mac、publisher_id、platform、account、series、timezone=Asia/Shanghai、source_chat、source_page、generator_task、publish_task、素材根目录和账本位置。账号及具体任务 ID 不写入公共仓库。先列出现有任务并读取内容、时区和状态，更新唯一既有任务，不另建同名任务。

默认生成 06:30；发布首查 07:05、补查 07:20/07:40。三个时间点必须续跑同一任务、同日草稿和同一账本。使用北京时间当天日期；过午夜禁止继续提交昨日草稿。补查可以恢复缺稿、缺图、断连；已提交只同步，最后窗口报告具体阻塞。每天动态核验账号、日期、标题和后台，不能沿用昨天的登录结论。

## 运行前检查

Python 执行环境需安装 Pillow（`python3 -m pip install "Pillow>=10,<13"`，按用户环境使用虚拟环境）。新脚本在 Mac/Linux 均用 Pillow 生成可验收的白底 JPEG；缺依赖则停止转换，不再自动调用无法等价验收的 sips。旧清单缺字段时，核对原件后在旁附清单补齐，不改写原 ZIP。

核实 Mac 在线、当前用户会话及所需浏览器可用、原有本地调度器确实能唤起执行、系统控制权限获准。睡眠、锁屏、退出登录、断网与平台验证都可能阻止执行；实际阻塞记 USER_ACTION_REQUIRED，不要求关闭锁屏或提取 Cookie。用户只在官方页面自行扫码或验证，不通过聊天收集验证码。已授权正常发布不重复确认。

素材持久目录按 platform/account/series/date 隔离，每日目录名是 YYYY-MM-DD。brief.md 保留完整原文，经脱敏后另存发布正文；manifest.json 含 date/timezone/content_version/images_expected 及每图 number/file/caption/sha256/width/height/section。ZIP SHA-256 记在包外的交接记录，不将 ZIP 自身哈希塞入内部 manifest。成功取回后实际重开文件并核验哈希、尺寸、PNG解码；来源临时路径或附件 ID 只是线索。归档不可用时不阻断已完整验证的本地包。

## 整体占用与提交账本

以 platform/account/series 为占用范围，版本和标题不能改变当天的去重标识。现有调度器必须串行执行完整浏览器流程；能调用命令执行器时，使用 `scripts/run_locked.py --lock /私有根目录/栏目/.publisher.lock -- 已有执行器 参数` 包住完整执行器进程。脚本只做本机互斥，不生成内容、不控制浏览器、不安装调度器；命令要等待整个执行完成，不能派生后台进程后提前返回。进程退出释放锁；后续运行仍先检查持久账本和后台，锁释放不代表未提交。

`brief_workflow.py` 的 `.workflow.lock` 仅保护单条命令的账本读写，不是浏览器会话锁，更不是跨主机共享锁。同一 Mac 发布者使用本机私有账本；若将来迁移，要先建立双方可读的原子占用与交接证据，再停旧启新。不得将网盘文件同步宣称分布式锁。

每次进入先读 `进度.json` 和后台。SCHEDULED/UNDER_REVIEW/PUBLISHED/REJECTED 及对应中文旧状态只同步；SUBMITTING/UNKNOWN 先查后台，不能排除已提交就停止。只有明确未提交且同一草稿已核验，才能 resolve-unsubmitted。预览、账号、全文、隐私、图注和公开范围检查后，以新鲜后台证据调用 begin-submit；只有返回 SUBMIT_ONCE 才单次点击，随后到笔记管理核实并 result 保存回执。已预约只记录预约；不能报告公开成功。

## 长文验收

首图使用选定封面，封面完整显示；逐处图片恰好一张，全部加载并紧邻对应图注。逐页检查末行裁切、全部段落和来源，删除临时标记；表格不兼容时逐行带列名保留所有单元格。从预览返回编辑后重新核实标题、简介、话题和公开范围，因为平台可能重置字段。近期三日的审核中记录只读同步；驳回通知，不自动重发。

## 交付状态必须分别记录

1. 代码：本地测试、Git commit、远端读回、CI 状态。
2. Mac 安装：实际路径与版本，现有任务是否已读回新规则。
3. 登录：当次官方页面账号核验与时间；历史登录不等于当前可用。
4. 持久化：原件和账本重开成功；原件哈希及原子提交保护通过。
5. 调度：现有任务时区、时间、唯一执行者以及实际触发记录。
6. 首次未来定时验收：从取稿到后台回执的下一次自然运行结果，未到时间记待运行。

没有本机工具或任务访问能力时完成代码交付，明确本机安装/调度未验证，不制造测试笔记，不虚报全链路部署。已有当天公开回执是禁止重发依据，不用于证明新版本未来调度已通过。
