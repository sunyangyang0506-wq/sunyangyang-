# 首次配置与授权

首次使用时读取已有任务与用户在当前环境授予的权限，先列出能够复用的部分。将实际缺项整合成一次简短的设置说明，再依次启动各服务的原生授权。由用户在服务提供的安全界面登录。聊天里的同意用于确定操作范围；连接成功、上传许可与发布状态分别用真实结果判断。

单次仅制稿时，跳过账号、上传、发布授权、跨任务回读和定时配置，直接按约定方式交付。只有实际要跨任务取件时才验证交接。

| 此次需要的能力 | 首次确定和验证 |
|---|---|
| 文章方向与来源 | 确定读者、栏目、资料来源、可公开的范围、配图格式和是否允许原件缺失时重制。读取用户指定的一份来源验证访问。使用公开资料时直接检索。只有依赖私人资料时才连接相应来源。 |
| 素材制作与交接 | 选用运行环境支持的写作、图片或视频能力，检查现有授权；如涉及新增费用，确认额度。指定私人存放位置，在制作端保存第一份真实发布包并从发布端按持久标识读回。 |
| 登录与文件上传 | 在实际用于发布的环境复用已登录账号，核对账号标识和后台昵称；缺失才发起平台支持的登录。对本次选定账号和素材说明上传目的，完成首次真实稿件的原生上传许可，在预览中核对实际媒体数量和封面。 |
| 发布范围 | 集中确认目标账号、栏目、仅制作／草稿／单次发布／持续发布、可见范围。持续发布还要确定频率、时区、开始条件和停止方式。用户已明确说明的项直接沿用。保存草稿与公开发布分别记录。 |
| 定时任务 | 仅在选定持续发布时查找同账号同栏目的已有任务。复用或更新匹配项；若缺失则在已确认范围内创建，并读回启用状态、时间、任务标识和发布环境。用定时任务的实际执行身份和环境验证私有配置、文件和目标账号的可用性；如果只能在交互会话验证，记录“定时运行待首轮验证”。让每次运行调用本 Skill，并引用私有配置和当期发布包。 |

用用户能理解的话一次补齐缺项，例如“为哪个账号、围绕什么主题、用哪些资料、多久发一次？原图取不到时，可以按同一篇正文制作新版吗？”有答案的字段从问题中删去。把账户连接、文件授权等原生请求集中在本次设置中推进。只在必须实际上传或提交时才出现的请求，随首篇真实稿件完成；未触发时标为待验证，避免用测试贴验证公开发布。拒绝、取消或撤回某一项时停止依赖该项的步骤，继续可独立进行的制作工作。

把配置保存在该用户可访问的私人空间。记录账号标识、栏目、来源和可公开范围、目的地、发布模式、时区、频率、授权范围及时间、配图降级策略、任务与存储标识，以及各连接的最近验证结果。不保留密码、验证码、Cookie 或令牌。再次执行时按该配置续跑，账号切换、权限扩大或授权失效时仅处理受影响项。停止持续发布时停用关联任务并记录撤回状态。平台要求再验证时在原步骤暂停，验证成功后先查重再续跑。


## 首次权限确认补充（与主 Skill v1.3.0 一致）

首次配置和后续发布均执行主 Skill 的 `permission_preflight` 权限矩阵。按“用户授权范围、执行工具写权限、平台账号身份、平台上传权限、平台提交权限、原图读取权限、安全验证”分别核实，不合并为笼统的“已授权”。

- 用户明确同意公开发布，不代表工具已获得浏览器控制、账号已登录或平台允许发帖。
- 对可读的授权范围和账号身份执行无副作用的检查；无法无副作用验证的提交权限保留 `UNKNOWN` 或 `UNVERIFIED_UNTIL_SUBMIT`，不得发布测试笔记验证。
- 平台原生登录、连接器授权及文件权限由实际用户账户完成；若需要扫码、短信或设备确认，只请求必要的本人交互，验证完成后复核权限。
- 只把最小权限状态、证据时间、账号、作用范围及阻塞节点写入私人记录，绝不保存验证码、Cookie、密码或令牌。
- 用户撤权、切换账号或授权范围变化时停止受影响的写操作，先复核再续跑。
