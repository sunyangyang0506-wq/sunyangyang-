# 首次使用：一次收集信息并完成必要授权

适用于任何使用者，不继承仓库作者或另一用户的账号、行业、原稿聊天、时区、定时安排及授权。先读取当前用户已有配置和本次要求，已明确的项直接复用；私人配置的 owner_key、账号及执行环境必须与当前使用者对应。多账号或多栏目各自建配置、素材目录及账本，不共享授权或成功记录。

## 1. 先检查，再一次提问

先发现当前可用的内容来源、发布工具、设备与存储。只读查看已有同账号同栏目的任务，避免重复创建。脚本的本机锁依赖 POSIX（Mac/Linux）；其他设备不得宣称已支持同一执行器，须先验证可用的等价工具与原子账本。不要询问可以从已授权工具直接获取的内部 ID、文件路径或技术参数。不要把缺浏览器的生成环境误认为发布环境。

将尚缺信息集中成**一份设置表**，通过当前支持的表单或一条消息收齐；如果提问工具限制题数，合并为一个自由文本设置表。用户可以一次回答全部，也可写“按建议”；只有已展示的非授权默认项可据此采用。明确的授权句才构成对应范围的授权，不把“按建议”、沉默或跳过当作公开发布许可。跳过非必需项不阻断；只有缺必需值或回答相互冲突时再补问具体缺项。不要先问账号、下一轮再问主题、再下一轮问频率。

| 一次收集的信息 | 需要用户决定的内容 | 可由执行者补齐／不必追问 |
|---|---|---|
| 目的与内容 | 仅制作、平台草稿、单次发布或持续发布；主题/栏目、读者、语言、图文/长文/视频 | 已给出的成稿即来源；仅制作无需平台账号或发布权限 |
| 来源与素材 | 使用公开资料还是指定私人来源；允许公开哪些资料；完整原稿同步还是允许改写；缺原图暂停还是允许按原文重制新版 | 读取一份真实样本验证；默认完整保留原稿、缺原件暂停，配图数按当期清单；新稿选题才制图 |
| 账号与可见范围 | 要使用的本人/获授权账号，平台支持的目标可见范围 | 先在实际发布环境读已登录账号并请用户确认尚未明确的归属；可用主页链接或昵称辨认，不要求用户找内部账号 ID |
| 执行与留存 | 使用哪台设备/已有云环境，文件留在哪里；是否启用可选私人归档 | 探测可用环境和私人目录给出建议；不能预设 Mac 或云已可用；无需购买云服务，归档默认不启用 |
| 持续发布安排 | 时区、首发时间、频率、开始日期、补查窗口、暂停/停止方式、异常通知位置 | 仅持续发布需要；平台预约一次稿件另收预约日期与时区；按实际调度能力安排，不承诺不支持的频率 |
| 操作授权 | 允许读取哪些来源、加工/脱敏哪些内容、上传哪个账号、保存草稿还是公开提交；持续授权是否覆盖后续同范围稿件；是否允许更新既有任务 | 不默认授予付费、删除旧帖、扩大账号权限或跨账号操作；费用默认 0，新增费用须另行明确授权 |

## 2. 同一次设置中完成原生权限流程

收到设置后自动推进所有**当前可验证且必要**的连接，不再逐项询问相同操作意图。用户提供的发布授权和系统/平台授权分别核验：

| 能力 | 如何获取与验证 | 何时必需 |
|---|---|---|
| 内容使用授权 | 保存用户明确允许的来源及公开范围、授权时间和原指令引用；读取真实样本 | 所有模式，仅限实际用到的资料 |
| 私人来源读取 | 服务自己的连接/选文件权限；打开指定文件，取回真实原图字节 | 采用私人来源时 |
| 制作能力 | 检查实际写作、图像或视频工具；未制出媒体不能声称已完成 | 需要新制作对应媒体时 |
| 私人存储读写 | 保存小型非敏感探针，在独立读取步骤核对后清理；不得写入公开仓库 | 需要持久交接/续跑时；输出文件仍按当前环境保存规则处理 |
| 浏览器或发布工具 | 使用当前环境允许的连接授权；Mac 的浏览器/辅助功能等权限按工具原生流程申请，不一概索取所有系统权限 | 保存平台草稿或发布时 |
| 平台登录与账号 | 在实际发布设备打开 https://creator.xiaohongshu.com/，读当前账号；必要时提供接管入口由本人完成官方登录，再核对账号 | 保存平台草稿或发布时 |
| 上传与预览 | 使用首篇真实稿件上传、逐图加载和预览，留证据；不能用空白或测试笔记探权 | 保存平台草稿或发布时，未走到此步记待首篇验证 |
| 提交授权与平台入口 | 保存明确的账号/栏目/可见范围/发布模式授权；检查实际入口。无法只读验证的能力随首篇真实稿件确认 | 仅公开或预约提交模式；授权不代表已登录或已公开 |
| 调度与跨运行复用 | 核对已存在任务，唯一发布者、时区、时间及执行身份；独立运行读取配置、素材、账本和会话，首轮自然运行验收 | 持续模式；临时进程或临时沙盒 crontab 不能当常驻部署 |
| 私人远程归档 | 验证目标确为私有、写入与固定版本实际字节读回 | 仅用户选用；可选失败不阻断已验证本地原件 |

遇原生授权页、扫码、短信或设备验证，按该工具要求交接本人操作，再继续剩余设置。不要在聊天索要验证码、密码，不读或搬运 Cookie/令牌。用户拒绝、取消或撤回时记录该项，停止依赖步骤，保留可继续部分。绝不预先同意未来未知权限、付费、账号权限扩大。

“一次完成”指在一次初始化流程中收齐已知信息并推进所有可获得的必要授权；平台以后要求再验证、当前尚不能触发的上传权限以及首轮未来运行，须真实记录待办，不能标成已获得。默认不发送测试笔记。

## 3. 保存可复用的私人配置

用 [空白配置模板](../assets/onboarding-profile.template.json) 为每位使用者/账号/栏目建立独立配置。模板所有授权与能力默认 UNKNOWN/未授予，无真实账号。实际 owner_key、profile_id 与目录由当前用户空间确定，不复用他人配置。不要让普通用户填写 JSON。

在私人位置初始化（已有配置不可覆盖）：

```bash
python3 scripts/onboarding.py init --config "$PROFILE_PATH"
python3 scripts/onboarding.py check --config "$PROFILE_PATH" --owner-key "$OWNER_KEY"
```

PROFILE_PATH 与 OWNER_KEY 从当前用户已授权的私人工作空间取得，不能用公共仓库或另一用户路径。现有配置缺字段时从已确认授权和真实证据补齐，不清空旧回执，不凭模板重新授予。再用 `scripts/onboarding.py check --config /私人目录/profile.json --owner-key 当前用户私有标识` 汇总缺项、必需权限、阻塞与待验证项。脚本只校验配置结构和证据记录，不发起登录、不授予权限、不安装调度、不证明平台发布。模板内的状态必须依据实际工具观察填写，不可为了通过检查批量改为 VERIFIED。

权限记录包括 status、checked_at、evidence_ref、runtime_id、account_id；与当前发布身份不匹配的证据无效。授权单独保存 granted、scope、recorded_at、instruction_ref；scope 包含 owner_key/account_id/series/mode/visibility/runtime_id 、来源/加工/隐私的 content_scope 和持续发布频率/时间的 schedule_scope。扩大资料范围或更换发布设备不能沿用旧授权证据。账户 Cookie/密码/验证码/令牌不进入配置、Git 或日志。持久配置和账本须在用户私人存储；这里只分发空白模板。

分别报告：信息已齐、用户授权范围已确认、连接已验证、上传/提交待首篇、调度已配置、首轮自然运行待验收。配置就绪不等于已发布。首次输出一份简短配置回执，列出目标、来源、设备、时间、授权范围、成功项和唯一剩余人工动作；无必要人工动作则直接续跑授权范围内工作。

## 4. 后续执行与变更

每次运行先比对当前用户、账号、栏目及配置；使用配置中的时区决定日期，不固定北京时间或七图。已确认选项不重问，已授权范围内不逐篇确认。实时核验会话、后台查重和实际预览，不把历史 VERIFIED 当作当次平台证据。账号切换、来源扩大、公开范围扩大、设备变更或撤权时，仅重新获取受影响的授权并使旧环境证据失效；重新同意后再继续。

用户暂停/撤回时，停止新提交并停用所关联的发布任务，保留审计记录；已有预约不会因停止调度自动取消，单独核对并按用户对预约的指示处理。提交结果未知仍须先核后台。Mac、云端与其他执行方式都只能保留一个实际发布者；既有 Mac 用户沿用 [Mac 运行与验收](mac-runtime.md)，不因通用化而自动迁移、重排程或重复创建任务。
