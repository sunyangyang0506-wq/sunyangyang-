# 小红书发布编排 Skill

## 0｜定位
本 Skill 不负责“想一个内容”，而负责把已经完成并核验的内容变成：
**可检查 → 可发布 → 可回溯 → 不重复发布** 的小红书发布流程。

上游：
- `xiaohongshu-alive-writer`
- `alive-oral-scriptwriter`
- `personal-visual-storyteller`

## 1｜输入
至少需要：
- 最终标题或标题候选
- 最终正文
- 图片/视频素材
- 目标账号/平台
- 来源与日期（资讯类）
- 用户授权状态
- 当前发布通道状态（若要自动发布）

## 2｜标准发布包
默认生成：
1. 标题：约20字，避免夸张和误导
2. 正文：移动端短段落
3. 100字左右摘要
4. 5–8个真实相关标签
5. 封面：优先3:4竖版
6. 信息卡/配图顺序
7. 发布检查清单
8. 发布状态与回执

资讯简报型内容建议：
`1张封面 + N张信息卡 + 1张结论/行动卡`

每张卡只保留：
- 1个标题
- 2–3个关键事实/数字
- 1句“为什么重要”

## 3｜发布前检查
所有项目必须通过。

### 内容
- 日期正确
- 数字正确
- 来源可核验
- 事实/分析已区分
- 未核实内容已标注
- 没有夸大标题
- 没有虚构亲历

### 图片
- 与新闻/主题直接相关
- 标注现场图 / 资料图 / 示意图
- 旧图不能冒充当天现场
- 无未授权他人影像
- 文字可读
- 版本与正文一致

### 隐私
- 无密码、验证码、Cookie、Token
- 无未授权个人信息
- 无内部业务资料
- 无隐藏在截图/背景中的敏感信息

### 平台
- 标题长度合理
- 正文可发布
- 标签相关
- 图片顺序正确
- 未出现明显平台禁用内容

## 4｜发布授权
### 可以自动发布的条件
同时满足：
1. 用户已明确授权本次发布，或已明确配置持续自动发布授权。
2. 当前执行环境存在可用的小红书发布通道。
3. 账号已登录。
4. 不需要用户额外输入验证码/二次确认。
5. 发布前检查全部通过。
6. 未发现重复笔记风险。

任意一项不满足：
**不得声称已发布。**

输出：
`已保存的发布包标识 + 中断步骤 + 可自动恢复的条件`

## 5｜重复发布保护
发布前建立指纹：
`发布日期 + 标题标准化 + 正文摘要hash + 主图hash（可用时）`

检查近期发布记录：
- 完全相同：阻止发布
- 高度相似：标记人工确认
- 同一日报同一天：默认阻止第二次发布

发布失败：
- 保留素材
- 记录失败原因
- 不自动重复点击发布
- 除非明确知道上次未成功且系统允许安全重试

## 6｜发布结果
成功后必须记录：
- platform
- account
- published_at
- post_id / note_id（若可获得）
- public_url（若可获得）
- title
- content_version
- media_version
- source_brief_version
- status

没有回执时：
不得仅凭页面跳转推断发布成功。

## 7｜自动化模式
适合每日简报等固定任务：

`首次配置与连接 → 本期选题与证据 → 成稿 → 配图与归档回读 → 查重 → 上传 → 回读标题、正文、封面和图片数 → 按授权提交 → 后台核验`

自动化不得：
- 用昨日素材冒充今日新闻
- 未生成图片却写“7图已完成”
- 发布失败后无限重试
- 未登录时伪造发布结果
- 因追求自动化跳过事实核验

## 8｜默认状态码
- `READY_TO_PUBLISH`
- `PENDING_USER_AUTH`
- `PENDING_LOGIN`
- `PENDING_2FA`
- `BLOCKED_BY_VALIDATION`
- `DUPLICATE_BLOCKED`
- `SUBMITTED_UNDER_REVIEW`
- `SUBMISSION_UNKNOWN`
- `PUBLISHED`
- `PUBLISH_FAILED`

## 9｜交付格式
### 发布检查
- 标题：PASS/FAIL
- 正文：PASS/FAIL
- 图片：PASS/FAIL
- 日期数字：PASS/FAIL
- 来源：PASS/FAIL
- 隐私：PASS/FAIL
- 重复发布：PASS/FAIL
- 发布通道：READY/BLOCKED

### 最终状态
只允许依据真实工具回执写：
- 已保存草稿或已预约，记录后台时间
- 已提交／审核中，记录账号、标题、提交时间及当期版本
- 已公开，记录可核实的链接或作品 ID（如有）
- 受阻待恢复、结果待核验或明确失败，记录证据和中断步骤

不得写模糊的“应该发出去了”。
