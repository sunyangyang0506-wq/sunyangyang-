# 附件恢复、浏览器连接与长文插图

## 执行开始与中断恢复

立即创建当期私人进度记录，写入触发时间和当前阶段；恢复先读它，再核对笔记管理及唯一草稿。定时任务存在且启用，不证明当天执行过。用运行记录区分“没有触发”“模型/网络中断”“源稿缺失”“媒体不可读”“平台失败”。只读取最新必要消息与当天记录，避免把整段历史、原图 base64 或完整页面反复写入对话造成上下文膨胀。

定时重试窗口从用户既有配置读取，使用同一稿件标识。早期可恢复失败保存进度等待补查；最后一次报告具体缺口、已插入图片数和草稿阶段。登录失效、设备锁定、隐私问题立即报告，同一问题当天提醒一次；用户回复恢复后仍需实际重查。连接恢复不意味着可重复提交。

## 从 ChatGPT 取回当期原件

1. 从指定聊天或 Page 确认完整日期、原文和原始图片清单。查看同日 ZIP、manifest 与正文，而非只有缩略图或摘要。图片数量依当期清单决定。
2. 优先使用连接器或页面真实下载控件，把文件落盘后读回。附件显示文件名、`sandbox:/mnt/data/...` 链接或生成端宣称校验通过，不代表发布端已取得字节。跨会话路径不能直接当成本地路径使用。
3. 附件卡打不开但原会话仍有文件时，可在该原稿聊天请求只恢复指定日的既有 ZIP：输出完整正文、按序文件名/图注/SHA-256，并用 `IPython.display.display(Image(data=原始PNG字节))` 直接展示原图；文件夹缺图时从同日 ZIP 取回。明确不重写、不重制、不混用其他日期。
4. 从已加载的实际图片下载原件，或在当前浏览器工具允许的只读范围内读取已渲染图片字节。遇到大字符串返回截断，分段读取再本地拼接；不要将 base64 打印到聊天。逐张核对取得字节与原始 manifest 的哈希，并解码查看。仅有图片尺寸或文件名不足以判定文件完整。
5. 用户要求截图时，只截原图区域，排除账户名、聊天界面及个人信息。展开后重新读取当前图名和边界，截图后目视检查。浮动聊天窗口可能遮挡查看器，展开控件也可能选错图片；不把遮挡图、空白图或错误图片记为已完成。若截图仍不可用且用户坚持截图交付，保留缺项并报告；用户允许原图文件时，使用已校验的原始字节，记录方法差异。
6. 保留原始 PNG。格式转换仅生成上传兼容副本，不覆盖原件，另记录转换格式与校验。不得把搜索来的类似图、生成的新图或其他日期图伪装成恢复原图。

实测兼容性：若大 PNG 写入二进制剪贴板后，粘贴立即导致浏览器本机通信断开，停止重复粘贴同一 PNG。保留原 PNG，使用系统图像工具生成相同像素的 JPEG 兼容副本，目视检查文字和颜色，再通过支持的 `image/jpeg` 剪贴板续传。记录原件与副本的各自哈希，不声称两者字节相同；不要把一次成功推断为所有尺寸的固定限制。

## 浏览器与剪贴板恢复

- 使用当前工具提供的浏览器和应用 API，先读其操作及故障文档。标签失效不等于浏览器断线，先重新获取同一浏览器中的目标标签。明确报告断线时才重新发现连接；连接编号可能变化，不能硬编码沿用。
- 单次点击或粘贴报错后，先检查正文、图片数量和焦点，排除其实已生效。工具调用失败不能算上传成功。必要时检查本机 Chrome 的当前窗口或扩展提示，处理普通可逆的连接问题；不改权限、不绕过安全限制、不安装替代扩展来逃避阻塞。
- 设备锁定或工具明确要求手动解锁时，保存进度，请用户解锁并保持屏幕唤醒。用户回复已解锁后重新验证；仍锁定则如实说明，不宣称已恢复。
- 浏览器可读但二进制粘贴失败时，先核实当前图片字节、剪贴板格式、编辑器焦点和实际上传状态，按工具文档恢复连接。替代上传控件仅在平台支持且能放回正确位置时使用。不要通过未支持的自动化接口绕过当前连接。

## 写长文：保留每张图片的位置

1. 去重后进入“写长文”，继续当期唯一草稿；没有才新建。将图号放在原稿位置的独立段落，例如 `〔插图1〕`，图注另起一段。先导入脱敏全文，再逐处插图。生成 HTML 时逐行识别 Markdown 标题，不能把同一块中标题之后的正文一并放进标题元素；检查标题只包含标题文本。
2. 逐个点击对应定位段落，使用工具支持的二进制剪贴板写入图片，在编辑器按系统粘贴快捷键。每次先记录已有图片数，等待新增图片上传和加载完成，再定位下一张，避免异步插入发生在后一个位置。
3. 一次粘贴可能产生重复图片，也可能只产生一张。按实际新增数量核对，不假设固定双份。确认同内容且多出的节点才删除；从后向前处理，先确认图片已被选中，再按删除键。不要删正文或未选中内容。
4. 每次局部操作后读取当前状态。删除定位符时只选择并核对该标记的准确文本，再删除；不能用全局正文选择来清理标记。
5. 最终逐张检查：预期位置恰好一张、图片已加载、原图顺序一致、紧邻正确图注。核对全文与来源、所有标题、表格单元格、首尾及唯一商业行动，无临时标记及用户个人信息。不要仅按总图数判断位置正确。
6. 用平台排版功能生成预览，等待预览完成；核对当天标题、页数、公开范围及每页可读性。平台模板自动增加的封面与原图分开计数，确认原图没有丢失或重复。
7. 发布控件若不在可访问树中，按工具支持的正常键盘 Tab 导航，必须从可见焦点确认是正确发布按钮后再执行。必要时使用截图可见坐标；不得调用隐藏应用内部方法。提交之前写入 `SUBMITTING`。
8. 发生超时、按钮没反应或页面异常时，先检查笔记管理；有审核中/公开记录就停止。如果无法确认未提交，保持 `UNKNOWN`。只有后台和草稿状态明确证明未提交才允许继续。

最终证据以笔记管理为准，保留能显示当期标题与审核/公开状态的截图。草稿、提交成功和公开成功分别报告。
