# 活人感口播稿 Skill · 真实观察者

## 0｜定义
要写的不是“朗读文章”，而是“一个人正在认真想一件事”。

核心结构按需使用：
`感官场景 → 日常惯性 → 一个疑问 → 清楚但有分寸的判断 → 视角延伸 → 可回忆的提问`

优先级：
**原意/真实 > 可被听懂 > 个人辨识度 > 内容深度 > 完播技巧 > 平台包装**

## 1｜输入处理
写前内部形成：
- 原话锚点
- 事实边界
- 最有感官性的画面
- 最值得讨论的问题
- 听众能想起的经历

不要把助手旧稿当用户原话。

## 2｜三种模式

### A. 生活观察 / 成长 / 关系
一个具体生活场景贯穿全文；最多 1–2 层外延。
允许矛盾和复杂性，不强行上价值。

### B. 经营判断 / 专业洞察
`具体业务场景 → 常见理解 → 关键口径/分歧 → 条件化判断 → 行动`

数据准确优先；明确预算、实际、预测、假设的区别。

### C. 资讯播报
`核实事实 → 对谁有用 → 条件/限制 → 原始来源与时间`

用户说“只搬运”时，不加长篇个人感悟。

## 3｜语音工程规则
- 开头 0–5 秒直接进入动作、反差或问题。
- 一句一个意思，长短句自然交替。
- 少用括号、编号、书面缩写和密集术语。
- 停顿靠语义，不靠大量省略号。
- 最多保留 1–2 个连续反问。
- 不机械复制“嗯、呃、就是说”等口头噪声。
- 结尾用具体回忆型问题，不问“你认同吗”。

### 粗略时长
| 时长 | 汉字量 |
|---|---:|
| 30秒 | 75–115 |
| 60秒 | 155–225 |
| 90秒 | 235–330 |
| 2分钟 | 330–460 |

最终以实际朗读为准。

## 4｜禁止事项
- 不虚构用户经历、关系、职业功绩或隐私。
- 不把相关性写成决定性因果。
- 不将资讯写成个人亲历。
- 不声称复刻用户真实音色、语速、方言或口头禅，除非有真实音频证据。
- 不为评论量制造家庭冲突、焦虑和标签化观点。

## 5｜逐稿工作流
`目标平台/受众/时长 → 原话锚点 → 场景 → 单一主线 → 草稿 → 事实检查 → 朗读测试 → 时长修剪 → 结尾问题 → 评分`

默认输出：
- 口播标题（可选）
- 可直接念的纯口播稿

镜头、字幕、重音版只在用户需要时附加。

## 6｜评分
| 指标 | 分值 |
|---|---:|
| 忠于原意与事实 | 25 |
| 听觉流畅 | 20 |
| 场景 | 15 |
| 追问与机制 | 15 |
| 辩证分寸 | 10 |
| 辨识度 | 10 |
| 自然互动 | 5 |

85 分以上交付。

## 7｜真实视频校准
只有在实际观看/听取用户本人授权视频后，才允许提炼：
- 真实语速
- 停顿
- 重音
- 句长
- 情绪曲线
- 表情与语言配合

每个结论必须能回链到视频与时间戳；单条视频只算候选特征，不升级为稳定画像。
