# Publish China care updates on X

帮助海外读者弄清在中国哪里可以获得可靠的就医信息、研究进展到了哪一步，以及下一步应该向谁核实。使用英文对外发布，使用中文向运营者报告。账号以独立资讯身份发言。先读 [信息源与证据](references/editorial.md)、[发布与咨询](references/operations.md)。[上海就医指南](references/example.json) 和 [靶向药监管公告](references/clinical-example.json) 都是可运行的演练样稿。

## 渠道隔离与重复执行
X 与小红书分别维护私有渠道配置、唯一执行者和回执。小红书选择 Mac 执行不代表 X 已绑定或已启用；不得复用另一平台的登录、任务或成功状态。每个幂等键包含 platform/account/series/date，内容版本另记，改标题或封面不能自动绕过去重。已预约、审核中或公开只同步；SUBMITTING/UNKNOWN 先查所选入口和平台，无法排除提交就保留阻塞。原始中文简报是线索与版本依据，英文衍生内容不覆盖源包。私有资料只进入已授权私有目录，公开仓库只存通用工具。

## 每期执行

1. 取北京时间营业日。查已有早报、选题历史、排程和发帖回执，早报只能提供线索。双语检索全部四条线：赴华服务和城市政策、重大科研和可行性研究、临床试验和药械监管、机构合作需求。优先广州、西安、上海、北京、海南博鳌乐城，并保留其他城市重大进展。一般回看 72 小时；扩大到 7 天时保留原日期。遇到撤回、停招或安全更新，优先核对已发旧帖。
2. 为候选记录事件日、发布日期、核对日、原文链接、来源机构和原始发布者。打开原文，在证据台账内将每条可发布英文主张对应到段落或表格。日期未知用 null。外媒转载、新闻稿译文和门户转发须追溯到同一个原始来源。链接打不开就换能直接支持该句的来源，或删去该句。
3. 先判断“研究进展”和“现在可用”各自有什么证据，再按参考表排序。每天选一个值得回答的具体问题，搭配一个补充视角。相关性不足时保留两条独立候选。没有新消息时可以发布当日重新核对、最近未发过的实用指南，显式标为 Service guide；没有合格内容就记录跳过。禁止为满足频率重发旧闻。
4. 写一条独立可读的英文主帖与一条英语视频跟帖。首句回答读者关心的问题；事实说清城市、机构、对象和边界，附直接原始来源。视频补充实际核实步骤或研究局限。图片和视频各自能独立理解。对专业人群按需定义缩写。适用时提出一个非敏感的导航或机构合作问题。临床或药品稿只给科学原文，不夹带招揽。允许研究稿当日没有 CTA。
5. 按 example.json 生成 edition.json。每期明示 publication_type、lane、stage、access、scope、sources、claims、public_copy、slides、review。临床类补 clinical 对象。以脚本校验和渲染，再对照原文逐句检查**所有**公开表面（图片、字幕、帖文和链接）。凡媒体来源未清、同名药混淆、临床阶段冲突、在本机构能否提供服务不明，一律缩小措辞或暂存。代码能检出结构错误，事实和权利须由执行者核实。
6. 在当日私有工作目录执行下列命令。使用 Python 3.9+、Pillow、ffmpeg（libx264）和 DejaVu 字体。工作目录、数据库、令牌、患者信息不得写入通用技能目录。把 SKILL_ROOT 指向本技能安装目录，在私有工作目录运行。

```bash
python3 "$SKILL_ROOT"/scripts/edition.py edition.json --out /private/path/edition
python3 "$SKILL_ROOT"/scripts/publish_x.py edition.json /private/path/edition --check
```

7. 用户已要求每日英文发布时，按 [账号绑定、图视频交付与回执](references/operations.md) 选择一个已绑定的发布入口。一个账号仅运行一个调度器。校验通过且两个媒体都准备好后才投递，保留发帖账号、提交时间、平台状态及最终 X 链接。重复运行先查回执。只发布事前允许的资讯；联网核验、来源、账号或媒体验收失败时给出准确状态。
8. 从本账号收到的主动询问中识别导航和合作需求。仅在用户授权的私有收件箱或 CRM 内整理。敏感内容直接交有资质的接收方；每日汇总仅含计数、下一步及资料缺口。使用 [咨询与归因规则](references/operations.md) 区分阅读、点击、有效咨询、机构对接和确认转介。

9. 写下一期前先复盘已发帖，再做内容升级。依照[读者反馈与改稿](references/reader-feedback.md)读取可见评论和分时汇总，识别显式需求，对照上一版实际文案写出英文改稿；在下一次可比窗口验证，保存结论。

## 对运营者的交付

报告选题与时间窗口、英文两段、原文链接、PNG、MP4、未发原因或两条回执、可归因的主动询问，以及次日要核实的事项。数据不可用写“不可观测”。首次运行核验账号身份、媒体路径、持久化状态和定时任务；演练写明模拟或只制作。禁止把定时任务已创建或发布平台已收件计作 X 发布成功。
