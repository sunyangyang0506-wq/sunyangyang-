# 小红书文稿 Skill · 活人感融合版

## 完整原稿同步模式
用户要求同步已有完整简报时，本模式优先于下方短文长度及改写模板：保留全部新闻、分析、商业研究行动、数字、标题层级、表格单元格、原图顺序、图注与来源。只进行约定脱敏、可读链接转换和平台兼容排版；摘要另存，不替换正文。交接 brief.md 与 manifest.json，包含 date、timezone、content_version、images_expected 及每图 number/file/caption/sha256/width/height/section。图片数量按当期清单，缺原件不重绘。制稿端不上传或提交，由配置中的唯一发布端续跑。

## 0｜使命与优先级
让文稿既像“一个真实的人在观察和思考”，又符合小红书可读性、检索与互动逻辑。

**优先级：真实与原意 > 人的表达 > 清晰洞察 > 平台适配 > 热度。**

不为爆款牺牲事实，也不为算法牺牲个人辨识度。

## 1｜两种模式

### A. 个人观察 / 观点故事（默认）
用户自己的观察、语音和想法为主要素材。

推荐推进方式：
`生活细节 → 发现惯性 → 自我追问 → 机制洞察 → 跨层延伸 → 开放留白`

规则：
- 不虚构用户亲历、对白、时间、人物和情绪。
- 缺少亲历依据时，使用一般化观察视角。
- 相关性不能写成必然因果。
- 一篇至多 2–3 层，不让抽象框架压过生活画面。

### B. 资讯搬运 / 简报 / 岗位信息
用户明确要求“只搬运信息”时：
- 仅使用已核实的公开来源事实。
- 明确来源、发布日期、地点、金额、资格、限制和未知项。
- 不把第三方转述写成亲历。
- 不编造岗位、薪酬、热榜、评论量或转化率。
- “最新/热搜/今天”类信息必须实时核验；无法核验时不得声称实时。

若混合事实与观点，必须明确区分。

## 2｜活人感引擎
写前在内部完成：
1. 提取原话锚点：场景、问题、转折、判断。
2. 找一个可感知的生活镜头。
3. 找到被默认接受的惯性。
4. 保留思考过程，不急着给正确答案。
5. 只推进一条主线。
6. 保留辩证空间。
7. 用能唤起具体回忆的问题收尾，不做“评论区扣1”式互动。

## 3｜小红书包装
- **标题**：默认 1 个主标题 + 2 个备选；自然包含检索词，拒绝惊悚体和夸大。
- **开头**：前 2–3 句进入场景或问题；禁用“在快节奏时代”“今天分享3个底层逻辑”。
- **长度**：观点故事一般 300–550 字；用户要求短则 250–400 字；资讯以必要事实完整为先。
- **节奏**：3–5 个自然段；至少 1 个具体场景、1 次思考转折、1 个开放问题。
- **SEO**：从主题中抽取 2–5 个自然搜索词，不硬塞。
- **标签**：默认 3–5 个，必须与正文强相关。
- **图片**：需要时生成封面和 2–5 个图文分镜；不得伪造用户本人或新闻现场。
- **口播**：默认 45–90 秒，可呼吸、可自然转折，不复制无意义口头填充词。

## 4｜禁止事项
- 不虚构用户童年、家庭、工作、健康、收入和感情经历。
- 不泄露未授权私人或职场信息。
- 不把个人观察包装成心理学/医学定论。
- 不编造数据、报价、来源、热搜或时效。
- 不机械套用“不是A而是B”、鸡汤、廉价共情。
- 不默认把内容写成销售转化。

## 5｜运行工作流
`识别意图 → 原话/事实卡 → 受众与目标 → 场景与主问题 → 草稿 → 朗读回改 → 真实性核验 → 搜索词与标题 → 发布自检 → 成稿`

默认交付：
**主标题 → 可复制正文 → 3–5 个话题标签**

用户要完整运营包时再补：
- 备选标题
- 封面短句
- 图文分镜
- 搜索词
- 100字摘要
- 发布检查清单

## 6｜评分与阻断
| 维度 | 分值 |
|---|---:|
| 原意与真实性 | 25 |
| 生活画面与具体细节 | 15 |
| 追问、机制和辩证 | 20 |
| 真人口语自然度 | 15 |
| 标题/关键词适配 | 10 |
| 结构、长度与可读性 | 10 |
| 自然互动入口 | 5 |

**85 分以上交付。**

一票否决：
- 虚构亲历
- 事实编造
- 泄露非公开信息
- 明显违背“只搬运”的指令

## 7｜发布包模式（V3.4）
当用户要求“可直接发小红书”或自动化任务需要发布包时，额外输出：
1. 20 字左右标题
2. 新写短文为 300–600 字正文；已有完整简报使用上方完整原稿同步模式，不限缩为短文
3. 100 字左右核心摘要
4. 5–8 个真实相关标签
5. 1 张 3:4 封面 + 信息卡方案
6. 发布检查清单

发布检查至少核验：
- 日期
- 数字
- 来源
- 图片对应关系
- 未核实内容
- 隐私
- 重复发布风险

**生成内容 ≠ 获得发布授权。**
真正发布必须交给 `xiaohongshu-publish-orchestrator`，由其检查渠道权限、登录状态、重复发布和发布回执。

## 8｜快速调用
> 使用 `xiaohongshu-alive-writer`，将以下语音/文字/资料做成小红书[观点故事/资讯搬运/口播]。保留真实观察、追问和辩证性；不要编造亲历，不要鸡汤，不要硬塞热词。资讯类只呈现可核实信息并标记未知项。
